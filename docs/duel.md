# 1대1 결투 (21·22단계 설계서)

2026-11-19 사용자가 정함(GDD 2.15): 모르는 사람과 매칭(GD-Sync 무료판), 웹판 없음, 서로 검으로 벤다, 곳은 언덕 싸움터, 각자 **검집의 검**을 들고 간다. 21단계는 규칙과 같은 PC 시험, 22단계는 온라인.

사용자가 자리에 없을 때 쓴 설계다. 아래 "가장 단순하게 정한 것"은 사용자가 바꿀 수 있다(바꾸기 전에는 이대로).

---

## 21단계: 결투 규칙과 같은 PC 시험

### 규칙

- **영주 둘.** `Rules.lords: Array`(0 = 나/방장, 1 = 상대). 지금의 `rules.lord`는 `lords[0]`을 가리켜 옛 코드가 그대로 돈다. 결투 모드(`Rules.duel = true`, `start_duel(sword_a, sword_b)`)에서는 낮밤·구역·뽑기·적이 없다.
- **틱.** `step_duel(input_a: LordInput, input_b: LordInput)`. 30Hz, 랜덤은 `Rules.rng` 하나, `state_hash`에 두 영주가 다 들어간다. 같은 시드·같은 입력이면 같은 결과(22단계가 이것에 기댄다).
- **맞히기.** `Moves`가 결투에서는 상대 영주를 맞힌다(판정 모양·늦게 터지는 것·날아가는 것·반격 자세 그대로). 구르기 무적, 넉백, 히트스톱은 적을 칠 때와 같다. 갈고리 검이면 우클릭 갈고리를 상대에게 건다.
- **검.** 각자 검집의 검 하나(검집이 비었으면 맨손). 결투에서는 부러지지 않는다. **각인과 고유 능력은 결투에서 끈다**(가장 단순하게 정한 것: 적을 상대로 만든 것이라 사람에게 그대로 쓰면 깨지는 것이 많다). 공격 방식(좌클릭 150가지)과 속성 피해는 켠다.
- **체력과 판.** 수치는 `data/duel.tres`(DuelData): 체력 300(둘 다 같다), 한 판 90초, 3판 2선승, 판 사이 3초. 시간이 다 되면 남은 체력 비율이 높은 쪽이 이긴다(같으면 비김, 그 판은 다시 하지 않는다).
- **곳.** 언덕 싸움터(34 × 22칸, 장애물 없음). 시작 자리는 가운데에서 좌우로 6칸씩, 서로 마주 본다.
- **보상.** 없다(가장 단순하게 정한 것). 결투 기록(이김·짐)만 `Meta`에 센다.
- **22단계 준비.** `LordInput`을 바이트로 바꾸고 되돌리는 함수(`to_bytes`/`from_bytes`)를 넣고 테스트한다.

### 같은 PC 시험

- **들어가기.** 마을 광장에 결투 말뚝 하나(기본 도형). E → 창: "같은 PC로 겨루기"(21단계), "모르는 사람과 겨루기"(22단계까지 흐리게). 1P와 2P가 차례로 검집에서 검을 고른다.
- **입력.** 1P는 키보드와 마우스(지금 그대로), 2P는 게임패드 0번(왼 스틱 이동, 오른 스틱 겨눔, RT 좌클릭, LT 갈고리, A 구르기). 게임패드가 없으면 2P는 가만히 서 있는다(시험용 허수아비가 된다).
- **카메라.** 같은 PC에서는 둘을 함께 담는 쿼터뷰 하나(둘 사이 가운데를 보고, 멀어지면 물러난다). 3인칭 화면 나누기는 하지 않는다(온라인에서는 각자 3인칭).
- **화면.** 영주 둘은 `LordView` 둘(2P는 망토 색을 어둡게 바꿔 구별). 위 가운데에 두 체력 막대와 판 점수(UI라 글자 괜찮다), 판이 끝나면 `Band`로 "1P 이김" 같은 한 줄, 다 끝나면 결과 창(UiKit) → 마을로. 세계에 글자 없음.
- **장면.** `scenes/duel/duel.tscn`, `scripts/duel/duel.gd`. 땅·하늘은 `HillBuilder`.

## 22단계: 온라인 매칭 (GD-Sync)

2026-11-19 방식은 **입력만 주고받는 락스텝**으로 정했다. 코드는 `scripts/net/`. 클라우드에는 키가 없어서 실제 접속은 해 보지 못했고(사용자 PC에서 확인 전), 락스텝은 전송과 떼어 가짜 전송(`LoopLink`)으로 시험했다.

### 구조

- `NetLink`(전송 인터페이스): `send(바이트, 믿는지)`, `received` 신호, `peer_joined`·`peer_left`, `is_host`(방을 만든 쪽), `status`(IDLE, NO_KEYS, CONNECTING, SEARCHING, WAITING, MATCHED, FAILED, CLOSED). 구현 둘.
  - `LoopLink`: 시험용. `LoopLink.pair(시드, 지연 최소, 지연 최대, 빠짐 확률)`로 둘을 이어 한 프로세스에서 주고받는다. 지연이 들쭉날쭉해 순서가 뒤섞이고, 믿지 못하는 전송은 빠진다(믿는 전송은 늦기만). 랜덤은 시드 있는 자체 RNG.
  - `GdSyncLink`: GD-Sync로. 아래 "GD-Sync 쪽".
- `Lockstep`(노드 없음, `NetLink`만 안다): 내 자리(0 = 방장, 1 = 손님), 입력 지연 D틱. `update(내 입력)`을 틱마다 부르면 내 입력을 tick+D 칸에 넣고 묶음을 보내고, 두 입력이 다 있는 틱만 `Rules.step_duel`로 넘긴다(돌렸으면 1, 상대 입력이 없어 기다리면 0 = 멈춤). 처음 D틱은 둘 다 빈 입력이다. 규칙은 한 줄도 바뀌지 않았고, 결과는 "입력을 D틱 미뤄 한 Rules로 그냥 돌린 것"과 같다(테스트가 본다).
- `DuelSetup`: 시작 정보(시드, 두 검 = 검 번호·검집 단계·검집 각인·검집에서 온 검인지). 바이트로 바꿔 보내고 되돌리며 검을 다시 만든다(`make_swords`). 상대가 보낸 값은 믿지 않고 다듬는다(모르는 검 번호·모양이 틀린 값은 맨손, 단계는 한계로, 각인은 아는 것만).
- `OnlineDuel`: 마을 창과 결투 장면 사이 흐름. `start(검)`으로 링크를 열고 → 맺어지면 `Lockstep.begin` → 준비되면 `ready` 신호 → 마을이 결투 장면으로 바꾼다. 결투 장면이 `OnlineDuel.current`(static)를 이어받는다.

### 프로토콜

- 모든 묶음의 첫 바이트가 종류다. 입력은 `[1][가장 늦은 틱 s32][내가 받은 상대 입력의 연속 끝 틱(ack) s32][개수 u8][LordInput 18바이트 × 개수]`, 한 묶음 10 + 18n바이트.
- 입력 묶음은 매 틱 믿지 못하는 전송(unreliable)으로 보낸다. 빠진 것은 상대가 알려 준 ack 다음 틱부터 다시 담아 메운다(최소 `net_resend_min` = 3틱은 늘 겹쳐 담고, 밀리면 `net_resend_max` = 24틱까지). 늦게 오거나 순서가 뒤바뀐 것은 틱 번호로 제자리에 넣고, 이미 있는 것은 덮어쓰지 않는다.
- `net_hash_every` = 30틱마다 `[2][틱 s32][state_hash s64]`(믿는 전송)을 주고받아 틱이 같은 것끼리 맞춘다. 다르면 `desync(틱)` 신호를 내고 더 돌리지 않는다.
- 시작: 양쪽이 `[3][버전, 내 검]`(HELLO, 믿는 전송)을 `net_hello_interval` 초마다 START를 받을 때까지 보낸다. 방장은 HELLO를 받으면 시드를 정해 `[4][DuelSetup]`(START)를 보낸다(HELLO가 또 오면 같은 START를 다시 보낸다). 버전(`net_version`)이 다르면 `peer_lost("version")`.
- 끊김: 링크의 `peer_left`는 `peer_lost("left")`. 상대 입력이 `net_timeout` = 6초 넘게 안 오면 `peer_lost("timeout")`. 그 전에는 기다리며 멈춘다(`stalled`).
- **시간.** 한 틱 = 호출 한 번이라 시계가 둘로 갈라지지 않는다. 결투 장면은 30Hz 시간 누적을 틱으로 쪼개 `update`를 부르고, 상대를 기다리는 동안은 쌓인 시간을 버린다(기다렸다가 몰아 돌지 않는다). 기다리는 중 한 줄 띠가 뜬다.

### 대역폭 (무료판 하루 200MB)

테스트(`tests/net_tests.gd`)가 지연 1~3틱·빠짐 5%에서 재서 출력한다: 한 쪽이 초당 약 2.5KB(묶음 평균 약 80바이트 × 30), 90초 3판(시작 2초·쉼 3초 포함 최대 약 290초)이면 한 쪽 약 0.7MB, 둘이 합쳐 약 1.4MB. 하루 200MB면 한 판 약 140번(플러그인의 암호화·헤더 겉치레를 ×2로 쳐도 약 70번). 실제 GD-Sync가 세는 방식은 접속해 봐야 안다.

### GD-Sync 쪽

- 플러그인: `addons/GD-Sync`(원래 이름 그대로, 버전 1.0.2, 저장소 https://github.com/GD-Sync/GD-Sync). 라이선스는 BSD 비슷한 글이지만 "소스 형태로 다시 나눠 줄 때 저작권과 면책 문구 유지, 이름을 홍보에 쓰지 않음"만 적혀 있고 BSD-2의 바이너리 조항은 없다(`addons/GD-Sync/LICENSE`). 소스 그대로 저장소에 넣었다. 내보낸 게임에 넣는 것은 약관(https://www.gd-sync.com/terms)을 사용자가 한 번 읽어 볼 것.
- **오토로드를 쓰지 않는다.** 플러그인의 오토로드(`GDSync`)는 장면이 없는 헤드리스 테스트(`-s`)에서 `current_scene`이 null이라 시작할 때 오류를 낸다. 그래서 project.godot에는 플러그인만 켜 두고(에디터의 GD-Sync 메뉴용), 게임에서는 `GdSyncLink`가 처음 쓸 때 `MultiplayerClient.gd`를 `/root/GDSync`로 올린다(이미 있으면 그것을 쓴다). 키가 없으면 올리지도 않는다.
- 흐름(소스 `MultiplayerClient.gd`의 API): `start_multiplayer()` → `connected` → `get_public_lobbies()` → `lobbies_received(목록)`에서 꼬리표 `game = geom_hill`, `mode = duel`, `ver = net_version`이고 열려 있고 안 찬 방을 이름순으로 고른다 → 있으면 `lobby_join`, 없으면 `lobby_create(이름 "gh_" + 10자, "", 공개, 2명, 꼬리표)` → `lobby_created` → `lobby_join` → 방을 만든 쪽이 방장(자리 0). 둘째가 들어오면 `client_joined`(또는 `lobby_get_all_clients`)로 맺어지고 방장이 방을 목록에서 감춘다(`lobby_set_visibility(false)`).
- 둘이 동시에 방을 만들면 서로 기다리게 된다: 기다리는 동안 `net_search_interval`마다 목록을 다시 보고, 이름이 더 앞선 다른 대기 방이 있으면 내 방을 나가 그리로 간다.
- 바이트 보내기: `/root/GdSyncRelay`(`gdsync_relay.gd`) 노드의 `receive(PackedByteArray)`를 `GDSync.expose_func`로 열어 두고, `call_func`(믿는 전송) / `call_func_unreliable`로 상대에게 부른다(노드 경로가 양쪽 같아야 한다). 이 노드가 시간도 흘려 준다(`poll`).
- 끝나면 방을 나가고(`lobby_leave`) 접속을 끊는다(`stop_multiplayer`).

### 키 넣는 법 (사용자)

키는 git에 올리지 않는다. 두 가지 중 하나를 하면 된다.

1. **파일(권장).** `user://gdsync_keys.cfg`를 만든다. 이 프로젝트의 이름은 "검의 언덕"이라 Windows에서는 `%APPDATA%\Godot\app_userdata\검의 언덕\gdsync_keys.cfg`(탐색기 주소창에 `%APPDATA%\Godot\app_userdata`를 붙여 넣으면 열린다. 폴더가 없으면 게임을 한 번 실행해 마을까지 들어가면 생긴다). 내용:
   ```
   [keys]
   public="공개 키"
   private="비밀 키"
   ```
   마을 결투 말뚝 → "모르는 사람과 겨루기"를 눌렀는데 키가 없으면 창이 이 파일의 실제 위치를 보여 준다.
2. **플러그인 메뉴.** Godot 에디터에서 Project > Tools > GD-Sync를 열어 Public Key·Private Key 칸에 붙여 넣으면 `addons/GD-Sync/keys.cfg`에 저장된다(`.gitignore`에 들어 있다). 이 파일과 환경변수 `GDSYNC_PUBLIC_KEY`·`GDSYNC_PRIVATE_KEY`도 읽는다(위 파일이 없을 때).

키는 gd-sync.com에서 계정을 만들고 대시보드에서 게임(API 키)을 만들면 공개 키·비밀 키 한 쌍이 나온다(플러그인 메뉴 안내문: "Please fill in an API Key so the engine may connect to the GD-Sync network."). 대시보드 화면은 클라우드에서 열어 보지 못해 메뉴 이름은 확인하지 못했다. 무료판은 한 방 4명, 하루 200MB(GDD 2.15).

실행 중에 키를 넣는 방법: 플러그인은 키를 `ConnectionController._PUBLIC_KEY`·`_PRIVATE_KEY` 변수에 시작 때 한 번 읽는다(`Scripts/KeyStore.gd`가 `addons/GD-Sync/keys.cfg`와 환경변수를 읽음, project.godot에는 더는 안 들어간다). 그래서 `GdSyncLink`가 `user://` 파일에서 읽은 키를 접속 전에 이 변수에 직접 넣는다. 플러그인을 새 버전으로 바꿔도 이 변수 이름이 같은지만 확인하면 된다.

### 같은 PC에서 창 둘로 시험하기

Godot 에디터에서 Debug > Customize Run Instances(실행 인스턴스 사용자 지정)로 "Enable Multiple Instances"를 2로 하고 실행하면 창 둘이 뜬다. 둘 다 마을 결투 말뚝 → "모르는 사람과 겨루기"를 누르면 서로 찾는다(같은 키 파일을 쓰고 같은 저장 파일도 쓴다: 한쪽 기록만 남을 수 있다).

## 정한 것

### 21단계 (2026-11-19)

설계서 그대로 만들었고, 애매한 곳은 가장 단순하게 정했다.

- **영주 둘.** `Rules.lords`(`lord`는 `lords[0]`, 비결투 모드는 하나). 영주마다 `DuelSeat`(검 칸, `Moves`, `Powers`, 날아가는 것, 맞힐 것)를 두고, `step_duel`이 영주 한 사람의 틱을 돌릴 때 `Rules`의 `lord`·`slots`·`moves`·`powers`·`projectiles`·`enemies`를 그 자리의 것으로 끼운다(`_seat`). 그래서 `Moves`와 `Rules._step_lord`는 한 줄도 바꾸지 않았다. 틱이 끝나면 늘 0번 자리로 돌아온다. 화면이 신호를 받을 때 누구 것인지는 `Rules.cur_seat`(신호는 동기로 불린다)로 안다.
- **맞히기.** 상대 영주는 **그림자 적**(`Enemy.seat >= 0`, 자리·체력·쓰러짐은 영주에서 틱마다 맞춘다)이라 `Moves`가 적처럼 맞힌다. `Rules.hurt`가 그림자 적이면 `_duel_hurt`로 가서 영주의 체력·무적·넉백을 쓴다. 영주 0이 먼저 돌고 1이 그다음이라 같은 틱에 서로 베면 둘 다 맞는다(둘 다 쓰러지면 그 판은 비김).
- **맞는 쪽.** 구르기 무적(`LordState.dash`), 맞은 뒤 무적(`DuelData.hurt_invuln` 0.3초, 적에게 맞을 때와 같은 값), 반격 자세(상대 `Moves.parried`, 반격은 그 영주 자리에서 돈다), 넉백(`knock_speed` × `DuelData.knockback_mult` 1), 히트스톱(`Rules.freeze` 하나를 같이 쓴다)은 적과 같은 수치다.
- **Powers.** `Powers.off`(using·holding은 false, ins·held는 0, 돌진 충전만 돈다). 좌클릭 수치 계산은 `Powers.stats()`가 그대로 하되 각인이 0이라 형태·등급·검집 보너스만 남는다. 속성 피해(불·얼음·벼락·피)는 `Moves._element`가 도는데, 그림자 적에 걸리는 불·얼음·출혈은 영주에게 아무 일도 안 하고(피해만), 피 속성의 체력 회복은 쓴다.
- **판.** 시작 전 2초 서 있기 → 싸움(입력이 먹는다) → 한 판이 끝나면 3초 쉼 → 다음 판. 쉬는 동안은 입력 없이 틱만 돈다(밀림·날아가는 것이 끝난다). 결투가 끝나면(`duel_over`) `Rules.phase`가 OVER가 되어 더 안 돈다. 비긴 판은 점수 없이 다시 하지 않고, 세 판을 다 치렀는데 점수가 같으면 결투도 비김.
- **몸 겹침.** 몸 크기 0.45칸(`DuelData.body_radius`)의 합보다 가까우면 반씩 밀어낸다.
- **검.** `Rules.start_duel(검, 검)`이 두 검의 내구를 없앤다(부러지지 않는다). 마을 창은 검집의 검(`Meta.sheath_sword`, 검집 강화 입음)과 맨손 중에서 고르고, 고른 것은 `Meta.duel_picks`(static, 저장 안 함)로 넘어간다. 검집이 비어 있으면 맨손뿐.
- **기록.** `Meta.duel_wins`(1P가 이김)·`duel_losses`(2P가 이김)는 저장하고 비김은 세지 않는다. 같은 PC에서는 1P를 나로 센다(22단계에서 온라인은 내가 이기고 진 것으로 센다). 도중에 Esc로 나가면 기록하지 않는다.
- **입력.** 1P는 마을과 같은 키보드·마우스(쿼터뷰라 겨눔은 마우스가 가리키는 땅), 2P는 게임패드 0번을 `Input.get_joy_axis`로 직접 읽는다(왼 스틱 이동, 오른 스틱 겨눔, RT 좌클릭, LT 갈고리, A 구르기). 새 입력 동작은 만들지 않았다. 패드가 없으면 2P는 가만히 선다. `duel.gd`의 `p1_source`·`p2_source`(Callable)에 함수를 넣으면 입력을 대신 줄 수 있다(시험과 22단계용).
- **22단계 준비.** `LordInput.to_bytes/from_bytes`: 깃발 1바이트 + swap_to + 이동·겨눔 32비트 실수 넷 = 18바이트. 되돌려도 같은 값이라 같은 틱·같은 입력이면 같은 `state_hash`다(`tests/duel_tests.gd`가 바이트를 거친 입력열도 본다).
- **화면.** `LordView`에 `seat`(결투에서 몇 번째 영주인지)만 더했다. 2P는 망토·몸 색을 바꿔 구별한다. 카메라는 `camera_rig`의 쿼터뷰를 쓰고 둘 사이 가운데를 보며 거리에 따라 배율만 바꾼다. 위 가운데에 체력 막대 둘·판 점수·남은 시간(`DuelHud`), 판이 끝나면 `Band` 한 줄, 다 끝나면 결과 창 → 마을. 세계에는 피해 숫자 말고 글자가 없다. 마을 광장의 결투 말뚝은 기본 도형(`VillageProps.duel_post`)이고 자리는 `lobby.gd`의 `duel_at`이다.
- **아직 안 한 것.** `MoveFx`의 따라가는 효과(회오리의 소용돌이 띠)가 늘 0번 영주를 따라간다(2P의 회오리 띠가 1P를 따라 보일 수 있음). 결투 소리는 4가지(휘두름·구르기·갈고리·맞음)만. 마을·결투 장면 손맛은 사용자가 PC에서 맞춘다.

### 22단계 (2026-11-19)

설계서(위)대로 만들었고, 애매한 곳은 가장 단순하게 정했다.

- **락스텝은 전송과 따로.** `Lockstep`은 `NetLink`만 알고 노드가 없다. `LoopLink` 둘과 `Rules` 둘로 지연 0~5틱·뒤섞임·빠짐 60%까지 매 틱 두 쪽 `state_hash`가 같은 것을 시험했다(`tests/net_tests.gd`). 결투 장면 둘을 한 프로세스에서 `LoopLink`로 이어 900틱 돌려도 같았다(임시 확인, 저장소에 두지 않음).
- **입력 지연.** `DuelData.net_delay` = 4틱(0.13초). 내 입력이 4틱 뒤에 먹는다. 더 줄이면 상대 입력이 늦을 때 멈추는 일이 늘고, 늘리면 둔하다. 손맛은 사용자가 PC에서 맞춘다.
- **자리.** 방을 만든 쪽이 0번(방장), 들어간 쪽이 1번. 화면은 자리와 상관없이 내 영주를 3인칭으로 따라가고 상대는 몸 색(푸른 망토)을 바꿔 구별한다. 막대 이름은 "나"와 "상대".
- **겨눔과 이동.** 온라인은 3인칭만이다(같은 PC는 그대로 쿼터뷰). 이동은 카메라 기준(`relative_move`), 겨눔은 카메라가 보는 쪽 3칸 앞(마을과 같은 방식)이고 마우스는 잡혀 있다(Esc로 나가기).
- **끝.** 이기고 지면 내 기록(`Meta.duel_wins/losses`)에 센다(온라인은 내가 이긴 것으로). 도중에 Esc로 나가거나 상대가 나가거나 desync가 나면 기록하지 않고 창 하나("연결이 끊겼다", "어긋났다") 뒤 마을로. 결과 창이 뜬 뒤 마을로를 누를 때 방을 나가고 접속을 끊는다. 상대가 먼저 나가면 마지막 몇 틱의 입력을 못 받을 수 있는데, 그때는 끊김으로 알린다.
- **다시 맞붙기 없음.** 끝나면 마을로 가서 다시 찾는다.
- **찾기 취소.** 찾는 창을 닫으면(Esc, 취소) 방을 나가고 접속을 끊는다. 상대를 기다리는 시간 한계는 없다.
- **키 없음.** 접속하지 않고 창에 "GD-Sync 키가 없습니다" 한 줄과 파일 위치·넣는 법을 보여 준다. 헤드리스 테스트와 키 없는 PC에서는 플러그인 노드도 올리지 않아 조용하다.
- **아직 안 한 것.** 실제 GD-Sync 접속은 사용자 PC에서 확인 전이다(키 없음 안내, 가짜 키로 "키가 틀렸다" 안내까지는 확인). 방 목록의 `Tags`·`Open` 칸 이름은 플러그인 소스(로컬 서버 구현)에서 읽었다. 윈도우와 리눅스처럼 운영체제가 다른 둘은 부동소수 계산이 달라 desync가 날 수 있다(같은 Windows 둘이면 같다). 온라인 중 일시정지·재접속은 없다(끊기면 끝).
