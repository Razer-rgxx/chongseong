# 1대1 결투 (21·22단계 설계서)

2026-11-19 사용자가 정함(GDD 2.15): 모르는 사람과 매칭(GD-Sync 무료판), 웹판 없음, 서로 검으로 벤다, 곳은 언덕 싸움터, 각자 **검집의 검**을 들고 간다. 21단계는 규칙과 같은 PC 시험, 22단계는 온라인.

사용자가 자리에 없을 때 쓴 설계다. 아래 "가장 단순하게 정한 것"은 사용자가 바꿀 수 있다(바꾸기 전에는 이대로).

---

## 21단계: 결투 규칙과 같은 PC 시험

### 규칙

- **영주 둘.** `Rules.lords: Array`(0 = 나/방장, 1 = 상대). 지금의 `rules.lord`는 `lords[0]`을 가리켜 옛 코드가 그대로 돈다. 결투 모드(`Rules.duel = true`, `start_duel(sword_a, sword_b)`)에서는 낮밤·구역·뽑기·적이 없다.
- **틱.** `step_duel(input_a: LordInput, input_b: LordInput)`. 30Hz, 랜덤은 `Rules.rng` 하나, `state_hash`에 두 영주가 다 들어간다. 같은 시드·같은 입력이면 같은 결과(22단계가 이것에 기댄다).
- **맞히기.** `Moves`가 결투에서는 상대 영주를 맞힌다(판정 모양·늦게 터지는 것·날아가는 것·반격 자세 그대로). 구르기 무적, 넉백, 히트스톱은 적을 칠 때와 같다. 갈고리 검이면 우클릭 갈고리를 상대에게 건다.
- **검.** 각자 검집의 검 하나(검집이 비었으면 맨손). 결투에서는 부러지지 않는다. **각인과 고유 능력은 결투에서 끈다**(가장 단순하게 정한 것: 적을 상대로 만든 것이라 사람에게 그대로 쓰면 깨지는 것이 많다). 공격 방식(좌클릭 150가지)과 속성 피해는 켠다.
- **체력과 판.** 수치는 `data/duel.tres`(DuelData): 체력 300(둘 다 같다), 한 판 90초, 3판 2선승, 판 사이 3초. 시간이 다 되면 남은 체력 비율이 높은 쪽이 이긴다(같으면 비김, 그 판은 다시 하지 않는다).
- **곳.** 언덕 싸움터(34 × 22칸, 장애물 없음). 시작 자리는 가운데에서 좌우로 6칸씩, 서로 마주 본다.
- **보상.** 없다(가장 단순하게 정한 것). 결투 기록(이김·짐)만 `Meta`에 센다.
- **22단계 준비.** `LordInput`을 바이트로 바꾸고 되돌리는 함수(`to_bytes`/`from_bytes`)를 넣고 테스트한다.

### 같은 PC 시험

- **들어가기.** 마을 광장에 결투 말뚝 하나(기본 도형). E → 창: "같은 PC로 겨루기"(21단계), "모르는 사람과 겨루기"(22단계까지 흐리게). 1P와 2P가 차례로 검집에서 검을 고른다.
- **입력.** 1P는 키보드와 마우스(지금 그대로), 2P는 게임패드 0번(왼 스틱 이동, 오른 스틱 겨눔, RT 좌클릭, LT 갈고리, A 구르기). 게임패드가 없으면 2P는 가만히 서 있는다(시험용 허수아비가 된다).
- **카메라.** 같은 PC에서는 둘을 함께 담는 쿼터뷰 하나(둘 사이 가운데를 보고, 멀어지면 물러난다). 3인칭 화면 나누기는 하지 않는다(온라인에서는 각자 3인칭).
- **화면.** 영주 둘은 `LordView` 둘(2P는 망토 색을 어둡게 바꿔 구별). 위 가운데에 두 체력 막대와 판 점수(UI라 글자 괜찮다), 판이 끝나면 `Band`로 "1P 이김" 같은 한 줄, 다 끝나면 결과 창(UiKit) → 마을로. 세계에 글자 없음.
- **장면.** `scenes/duel/duel.tscn`, `scripts/duel/duel.gd`. 땅·하늘은 `HillBuilder`.

## 22단계: 온라인 매칭 (GD-Sync)

- 사용자가 GD-Sync에 가입해 키를 받아야 한다(키는 git에 올리지 않는다: `user://` 또는 무시되는 설정 파일).
- 방식은 22단계를 시작할 때 고른다. 후보: 방장이 규칙을 돌리고 상대는 입력만 보내 방장이 상태를 돌려준다(쉬움, 상대는 늦게 느낀다) / 입력만 주고받는 락스텝에 입력 지연 몇 틱(규칙이 결정적이라 가능, 둘 다 똑같이 늦다). GD-Sync 무료판의 하루 200MB 안에 들게 입력만 보내는 쪽을 먼저 본다.
- 매칭: GD-Sync 공개 방 찾기 → 없으면 방 만들고 기다림. 각자 3인칭.

## 정한 것

### 21단계 (2026-11-19)

설계서 그대로 만들었고, 애매한 곳은 가장 단순하게 정했다.

- **영주 둘.** `Rules.lords`(`lord`는 `lords[0]`, 비결투 모드는 하나). 영주마다 `DuelSeat`(검 칸, `Moves`, `Powers`, 날아가는 것, 맞힐 것)를 두고, `step_duel`이 영주 한 사람의 틱을 돌릴 때 `Rules`의 `lord`·`slots`·`moves`·`powers`·`projectiles`·`enemies`를 그 자리의 것으로 끼운다(`_seat`). 그래서 `Moves`와 `Rules._step_lord`는 한 줄도 바꾸지 않았다. 틱이 끝나면 늘 0번 자리로 돌아온다. 화면이 신호를 받을 때 누구 것인지는 `Rules.cur_seat`(신호는 동기로 불린다)로 안다.
- **맞히기.** 상대 영주는 **그림자 적**(`Enemy.seat >= 0`, 자리·체력·쓰러짐은 영주에서 틱마다 맞춘다)이라 `Moves`가 적처럼 맞힌다. `Rules.hurt`가 그림자 적이면 `_duel_hurt`로 가서 영주의 체력·무적·넉백을 쓴다. 영주 0이 먼저 돌고 1이 그다음이라 같은 틱에 서로 베면 둘 다 맞는다(둘 다 쓰러지면 그 판은 비김).
- **맞는 쪽.** 구르기 무적(`LordState.dash`), 맞은 뒤 무적(`DuelData.hurt_invuln` 0.3초, 적에게 맞을 때와 같은 값), 반격 자세(상대 `Moves.parried`, 반격은 그 영주 자리에서 돈다), 넉백(`knock_speed` × `DuelData.knockback_mult` 1), 히트스톱(`Rules.freeze` 하나를 같이 쓴다)은 적과 같은 수치다.
- **Powers.** `Powers.off`(using·holding은 false, ins·held는 0, 돌진 충전만 돈다). 좌클릭 수치 계산은 `Powers.stats()`가 그대로 하되 각인이 0이라 형태·등급·검집 보너스만 남는다. 속성 피해(불·얼음·벼락·피)는 `Moves._element`가 도는데, 그림자 적에 걸리는 불·얼음·출혈은 영주에게 아무 일도 안 하고(피해만), 피 속성의 체력 회복은 쓴다.
- **판.** 시작 전 2초 서 있기 → 싸움(입력이 먹는다) → 한 판이 끝나면 3초 쉼 → 다음 판. 쉬는 동안은 입력 없이 틱만 돈다(밀림·날아가는 것이 끝난다). 결투가 끝나면(`duel_over`) `Rules.phase`가 OVER가 되어 더 안 돈다. 비긴 판은 점수 없이 다시 하지 않고, 세 판을 다 치렀는데 점수가 같으면 결투도 비김.
- **몸 겹침.** 몸 크기 0.45칸(`DuelData.body_radius`)의 합보다 가까우면 반씩 밀어낸다.
- **검.** `Rules.start_duel(검, 검)`이 두 검의 내구를 없앤다(부러지지 않는다). 마을 창은 검집의 검(`Meta.sheath_sword`, 검집 강화 입음)과 맨손 중에서 고르고, 고른 것은 `Meta.duel_picks`(static, 저장 안 함)로 넘어간다. 검집이 비어 있으면 맨손뿐.
- **기록.** `Meta.duel_wins`(1P가 이김)·`duel_losses`(2P가 이김)는 저장하고 비김은 세지 않는다. 같은 PC에서는 1P를 나로 센다(22단계에서 온라인은 내가 이기고 진 것으로 센다). 도중에 Esc로 나가면 기록하지 않는다.
- **입력.** 1P는 마을과 같은 키보드·마우스(쿼터뷰라 겨눔은 마우스가 가리키는 땅), 2P는 게임패드 0번을 `Input.get_joy_axis`로 직접 읽는다(왼 스틱 이동, 오른 스틱 겨눔, RT 좌클릭, LT 갈고리, A 구르기). 새 입력 동작은 만들지 않았다. 패드가 없으면 2P는 가만히 선다. `duel.gd`의 `p1_source`·`p2_source`(Callable)에 함수를 넣으면 입력을 대신 줄 수 있다(시험과 22단계용).
- **22단계 준비.** `LordInput.to_bytes/from_bytes`: 깃발 1바이트 + swap_to + 이동·겨눔 32비트 실수 넷 = 18바이트. 되돌려도 같은 값이라 같은 틱·같은 입력이면 같은 `state_hash`다(`tests/duel_tests.gd`가 바이트를 거친 입력열도 본다).
- **화면.** `LordView`에 `seat`(결투에서 몇 번째 영주인지)만 더했다. 2P는 망토·몸 색을 바꿔 구별한다. 카메라는 `camera_rig`의 쿼터뷰를 쓰고 둘 사이 가운데를 보며 거리에 따라 배율만 바꾼다. 위 가운데에 체력 막대 둘·판 점수·남은 시간(`DuelHud`), 판이 끝나면 `Band` 한 줄, 다 끝나면 결과 창 → 마을. 세계에는 피해 숫자 말고 글자가 없다. 마을 광장의 결투 말뚝은 기본 도형(`VillageProps.duel_post`)이고 자리는 `lobby.gd`의 `duel_at`이다.
- **아직 안 한 것.** `MoveFx`의 따라가는 효과(회오리의 소용돌이 띠)가 늘 0번 영주를 따라간다(2P의 회오리 띠가 1P를 따라 보일 수 있음). 결투 소리는 4가지(휘두름·구르기·갈고리·맞음)만. 마을·결투 장면 손맛은 사용자가 PC에서 맞춘다.
